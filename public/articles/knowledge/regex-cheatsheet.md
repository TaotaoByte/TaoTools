# 常用正则表达式速查

正则表达式（Regular Expression）是处理文本的利器，无论是表单校验、日志分析还是代码搜索，都离不开它。本文整理最常用的语法与现成模板，配合本站的「正则表达式测试」工具可以随时验证。

## 一、基础元字符

| 元字符 | 含义 | 示例 |
|--------|------|------|
| `.` | 匹配除换行外的任意字符 | `a.c` 匹配 `abc`、`a1c` |
| `\d` | 数字，等价 `[0-9]` | `\d+` 匹配 `123` |
| `\w` | 字母数字下划线 | `\w+` 匹配 `abc_123` |
| `\s` | 空白字符（空格、Tab、换行） | `\s+` 匹配连续空白 |
| `\b` | 单词边界 | `\bcat\b` 只匹配独立的 `cat` |
| `^` | 行的开头 | `^abc` 匹配以 abc 开头 |
| `$` | 行的结尾 | `abc$` 匹配以 abc 结尾 |

## 二、字符类与量词

字符类用方括号表示「任意一个」：

```text
[aeiou]    # 任意一个元音字母
[a-z]      # 任意一个小写字母
[A-Za-z]   # 任意字母
[^0-9]     # 任意非数字
```

量词指定「重复次数」：

| 量词 | 含义 |
|------|------|
| `*` | 0 次或多次 |
| `+` | 1 次或多次 |
| `?` | 0 次或 1 次 |
| `{n}` | 恰好 n 次 |
| `{n,}` | 至少 n 次 |
| `{n,m}` | n 到 m 次 |

示例：

```text
\d{4}          # 恰好 4 位数字，如年份
\d{2,4}        # 2 到 4 位数字
\w+@\w+\.\w+   # 简单的邮箱结构
```

## 三、分组与捕获

括号用于分组，并默认「捕获」匹配结果：

```text
(ab)+         # 匹配 ab、abab、ababab
(\d{3})-(\d{4})  # 捕获区号与尾号
```

如果只想要分组而不需要捕获，使用非捕获分组 `(?:...)`：

```text
(?:https?)://
```

反向引用可引用已捕获的内容：

```text
(\w+)\s+\1    # 匹配重复出现的单词
```

## 四、常用断言

断言（lookaround）用于匹配「某个位置」，不消耗字符：

| 断言 | 含义 |
|------|------|
| `(?=...)` | 后面紧跟 |
| `(?!...)` | 后面不紧跟 |
| `(?<=...)` | 前面是 |
| `(?<!...)` | 前面不是 |

示例：

```text
\d+(?=元)        # 匹配「元」前面的数字
(?<=￥)\d+       # 匹配「￥」后面的数字
(?!.*密码).*     # 匹配不包含「密码」的行
```

## 五、常用模式标志

- `i`：忽略大小写
- `g`：全局匹配
- `m`：多行模式，`^` 和 `$` 匹配每行的开头结尾
- `s`：单行模式，`.` 也能匹配换行

## 六、实用正则模板

这些模板可以直接复制使用：

```text
# 手机号（中国大陆）
^1[3-9]\d{9}$

# 邮箱
^[\w.+-]+@[\w-]+\.[\w.-]+$

# URL
^https?://[\w.-]+(?:\.[\w.-]+)+[^\s]*$

# 18 位身份证（简单校验）
^\d{17}[\dXx]$

# 日期 YYYY-MM-DD
^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$

# IPv4 地址
^((25[0-5]|2[0-4]\d|1?\d?\d)\.){3}(25[0-5]|2[0-4]\d|1?\d?\d)$

# 提取中文字符
[\u4e00-\u9fa5]

# 去除首尾空白
^\s+|\s+$
```

## 七、常见坑

1. **贪婪 vs 非贪婪**：默认 `*` 和 `+` 是贪婪的，会尽量多匹配。加 `?` 变为非贪婪，如 `.*?`。
2. **特殊字符转义**：`.^$*+?()[]{}|/` 这些字符作为字面量匹配时需要转义，如 `\.`。
3. **性能**：避免在长文本中使用会产生大量回溯的嵌套量词，如 `(a+)+`。
4. **中文匹配**：使用 Unicode 范围 `[\u4e00-\u9fa5]` 来匹配常用汉字。

## 八、总结

正则的入门并不难，关键是记住「元字符 + 量词 + 分组 + 断言」这四块核心。遇到复杂的校验需求时，先从现成模板出发，再用测试工具逐步调试，会比从头写高效得多。
