# 个人网站上线前，我会检查的十件事

页面能打开，只是发布检查的开始。下面这份清单适用于工具站和个人博客，可以在每次修改后花几分钟过一遍。

## 页面和入口

- [ ] 用手机宽度打开首页，确认导航可用，标题和按钮没有挤出屏幕。
- [ ] 从首页点击一个具体工具，应该直接进入那个工具，而不是重新找一遍。
- [ ] 复制文章或工具地址，在新标签页打开；再刷新一次，检查深链接。
- [ ] 用浏览器后退和前进，确认地址与显示内容一致。
- [ ] 用键盘 Tab、Enter 和空格操作入口，确认焦点看得见。

## 内容和数据

- [ ] 查一遍简介里的年级、求职方向、联系地址，只更新确定的信息。
- [ ] 上传、删除、发布操作先用临时内容试一次。删除草稿不应该顺带删除已发布文章。
- [ ] 看看文章列表里的日期、分类、封面和搜索结果是否与正文一致。

## 构建和环境

- [ ] 在推送前完成生产构建和类型检查；不能依靠忽略错误来判断可上线。
- [ ] 区分本地管理后台与公开前端：公开前端不能依赖访问者电脑上的 localhost 服务。API 密钥留在服务端环境变量里。

## 发现密钥曾经进入代码怎么办

先在服务提供方撤销或更换旧密钥，再改用环境变量。只删除当前文件里的密钥，不能让历史提交中的旧值失效。是否清理仓库历史要单独评估，避免在没有协调的情况下强推覆盖其他人的工作。

参考：[GitHub：从仓库移除敏感数据](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

## 最后留一条发布记录

记下提交号、检查结果和需要手动配置的环境变量。推送成功和部署成功是两个状态；如果没有看到部署结果，就把它标记为待确认。
