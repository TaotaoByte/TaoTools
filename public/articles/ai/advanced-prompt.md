# Prompt 工程进阶：让 AI 输出更精准

## 引言：Prompt 是人与 AI 的接口

如果说大模型是强大的发动机，那么 Prompt 就是驾驭这台发动机的方向盘。同样一个问题，提示词写得好不好，直接决定了 AI 输出的质量、准确度和可用性。

很多人刚开始使用 AI 时，习惯于用零散、口语化的方式提问。虽然大模型足够聪明，能够理解大部分意图，但这种方式就像是在开盲盒：结果时好时坏，不可预测。真正高效的用法，是把 Prompt 当作一门工程学科来设计：明确目标、提供上下文、控制输出、持续迭代。

本文将从角色设定、上下文工程、Few-shot、Chain-of-Thought、结构化输出、任务拆解、迭代优化和常见反模式八个方面，带你系统掌握 Prompt 工程的进阶方法。

## 角色设定与上下文工程

### 角色设定：让 AI 进入状态

给 AI 设定一个具体角色，可以迅速约束它的回答风格、知识领域和价值观。例如：

```text
你是一位有 15 年经验的产品经理，擅长把复杂的技术概念用通俗语言解释给非技术背景的高管听。
```

角色设定的好处是显而易见的：它让 AI 知道自己“应该像谁一样说话”，从而减少泛泛而谈，提高专业度。

在实际使用中，角色可以有很多种：

- **领域专家**：资深前端架构师、数据分析师、法律顾问
- **岗位角色**：技术面试官、内容编辑、客户成功经理
- **风格角色**：幽默的科普作家、严谨的学术审稿人、简洁的文案高手

一个好的角色设定通常包含：身份、经验年限、擅长领域、目标受众、输出风格。

### 上下文工程：给 AI 足够的背景

上下文工程是指在与 AI 交互时，主动提供它完成任务的必要背景信息。上下文越充分，AI 越容易给出精准答案。

上下文可以包括：

- 任务目标和边界
- 相关数据或文档
- 输出格式要求
- 质量标准和评估指标
- 已知约束和禁忌

例如，在让 AI 撰写一份产品需求文档时，可以这样提供上下文：

```text
背景：我们正在为一款面向大学生的记账 App 设计新功能。
目标用户：18-25 岁的大学生，注重简洁和隐私。
功能目标：帮助用户通过拍照自动识别消费小票并生成记账记录。
输出要求：按用户故事、功能流程、界面草图描述、数据字段四部分撰写，控制在 1000 字以内。
```

## Few-shot 与 Chain-of-Thought

### Few-shot Prompting：用示例教会 AI

Few-shot 是指在提示词中提供几个输入-输出示例，让 AI 学习你期望的格式和风格。这种方法特别适合风格化生成、分类、翻译、数据提取等任务。

例如，想让 AI 把口语化描述转换成标准的产品需求：

```text
输入：用户想在一个页面上看到所有订单
输出：作为用户，我希望在“我的订单”页面查看全部历史订单，包括订单号、商品名称、下单时间和订单状态。

输入：用户希望能收到发货提醒
输出：作为用户，我希望在订单发货时通过 App 推送收到通知，以便及时了解物流进展。

输入：用户想修改收货地址
输出：
```

通过示例，AI 不仅学会了输出格式，还学会了语气和粒度。

### Chain-of-Thought：让 AI 先思考再回答

Chain-of-Thought（CoT，思维链）是一种引导 AI 逐步推理的提示技巧。对于数学、逻辑、决策等复杂问题，明确要求 AI 先展示思考过程，再给出结论，可以显著提高准确率。

例如：

```text
请一步一步思考：一个水池有两个水管，A 管单独注满需要 6 小时，B 管单独注满需要 4 小时。如果两个水管同时打开，需要多久注满？请先写出推理过程，再给出最终答案。
```

CoT 的关键在于“显式要求推理过程”。你也可以把复杂问题拆成多个小问题，让 AI 逐一回答。

## 结构化输出：JSON、XML 与 Markdown

大模型生成非结构化文本时，容易出现格式不一致、信息遗漏的问题。通过要求结构化输出，可以大幅提升结果的可解析性和可用性。

### JSON 输出

JSON 是最常用的结构化格式，特别适合程序化处理：

```text
请从以下用户评价中提取关键信息，并以 JSON 格式返回：
{
  "sentiment": "正面/负面/中性",
  "mentioned_features": ["功能1", "功能2"],
  "suggestions": ["建议1"],
  "summary": "一句话总结"
}
```

对于需要严格 schema 的场景，建议明确字段类型、是否必填、枚举值等约束。

### XML 输出

XML 适合层次结构明显的内容，比如文章大纲、多层级分类：

```xml
<outline>
  <section title="引言">
    <point>背景介绍</point>
    <point>问题提出</point>
  </section>
</outline>
```

### Markdown 输出

Markdown 是文档和演示场景的首选，既保留了结构，又便于人工阅读：

```text
请用 Markdown 表格对比三款产品的优缺点。
```

选择哪种格式，取决于后续如何使用：程序解析用 JSON，层次内容用 XML，人读用 Markdown。

## 拆解复杂任务

复杂任务一次性丢给 AI，往往会导致输出冗长、重点分散、逻辑混乱。更好的做法是“分而治之”。

一个典型的拆解流程是：

1. **任务分解**：把大任务拆成多个独立子任务。
2. **逐一执行**：逐个让 AI 完成每个子任务。
3. **汇总整合**：把各子任务结果合并成最终输出。

例如，让 AI 帮你写一份行业研究报告：

```text
第一步：请总结新能源汽车行业近三年的市场规模和增长率。
第二步：请列出该行业前五名企业的核心竞争优势。
第三步：请分析行业面临的三大挑战。
第四步：请基于以上信息，撰写一份 800 字的行业研究报告摘要。
```

拆解任务有两个好处：一是降低了单次提示的复杂度，二是方便你在每个环节进行人工干预和质量控制。

## 迭代优化 Prompt

Prompt 工程 rarely 一次成功。优秀的提示词通常需要多轮迭代才能成型。

### 迭代步骤

1. **初版**：用自然语言描述需求，获得第一版输出。
2. **评估**：检查输出是否满足目标，找出问题。
3. **修正**：针对问题调整提示词，比如增加约束、补充示例、明确格式。
4. **再测试**：再次运行，观察改进效果。
5. **固化**：把效果稳定的提示词整理成模板。

### 常见的优化方向

- **增加约束**：限制字数、格式、语气、使用场景。
- **补充示例**：用 Few-shot 引导风格。
- **明确受众**：告诉 AI 内容给谁看。
- **分步骤**：要求 AI 按固定流程输出。
- **加入评估标准**：让 AI 自检输出质量。

例如，初版提示：

```text
写一段产品推荐语。
```

迭代后：

```text
请为一款面向职场新人的降噪耳机写一段 150 字的产品推荐语。
目标受众：22-30 岁、经常出差、注重性价比的职场新人。
语气：亲切、专业、略带紧迫感。
要求：突出降噪效果、续航时间和价格优势，结尾包含行动号召。
```

## 常见反模式与避免方法

### 1. 提示过于模糊

模糊的提示会得到模糊的回答。避免只说“帮我写一下”、“分析一下”，而要说明目标、格式、长度、风格。

### 2. 一次性要求过多

把太多任务塞进一个提示，会让 AI 顾此失彼。建议拆分成多个步骤或多个提示。

### 3. 缺乏输出约束

如果不指定输出格式，AI 可能输出大段散文，难以使用。提前说明格式要求可以避免反复修改。

### 4. 忽视上下文长度限制

虽然模型上下文越来越长，但过长的无关信息会稀释重点。只提供与任务相关的上下文。

### 5. 盲目相信第一次输出

AI 也会犯错。重要内容需要人工核对，尤其是涉及事实、数据、代码和安全规则时。

### 6. 不善于使用系统提示

在支持系统提示的模型中，把稳定的角色、规则、约束放在系统提示里，把具体任务放在用户提示里，可以让交互更加清晰和稳定。

## 结语

Prompt 工程不是玄学，而是一门可以通过练习不断提升的技能。它的核心在于：把模糊的人类意图，转化为清晰、结构化、可执行的机器指令。

掌握角色设定、上下文工程、Few-shot、Chain-of-Thought、结构化输出、任务拆解和迭代优化，你就已经超越了绝大多数 AI 用户。更重要的是，要养成复盘和整理提示词的习惯，把自己的经验沉淀成可复用的模板。随着模型能力不断增强，善于写 Prompt 的人，将能释放出远超他人的生产力。
