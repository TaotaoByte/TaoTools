# 用 AI 进行代码审查的提示词

代码审查（Code Review）是保证代码质量的重要环节，但人工审查耗时且容易忽略细节。让 AI 充当「第一道审查者」，可以帮你先扫一遍常见问题，再人工做关键决策。本文分享一套可直接复用的审查提示词。

## 一、为什么要让 AI 参与审查

AI 在以下方面有明显优势：

- **覆盖面广**：能同时关注安全、性能、可读性、边界情况等多个维度。
- **速度快**：几秒内给出初步意见，再人工甄别。
- **不遗漏常见模式**：对 SQL 注入、XSS、资源泄漏等常见问题有稳定识别能力。

需要注意：AI 也可能误报或遗漏，所以它只能作为「辅助」，最终结论仍需人工判断。

## 二、通用代码审查提示词

```text
请以资深后端工程师的身份，审查以下代码，逐条列出发现的问题。

请重点关注：
1. 安全性（SQL 注入、XSS、CSRF、敏感信息泄露、不安全的加密）；
2. 正确性（边界情况、空值处理、异常处理）；
3. 性能（不必要的循环、重复计算、资源未释放）；
4. 可维护性（命名、重复代码、复杂度、可测试性）。

格式要求：
- 按「问题描述 / 严重程度（高/中/低）/ 建议修改」组织；
- 如果代码没有问题，明确说出「未发现明显问题」。
```

## 三、按语言定制

针对不同语言，可以增加特定的关注点。比如前端代码：

```text
请审查以下前端代码，额外关注：
1. React 性能（不必要的重渲染、缺失的 key、副作用位置）；
2. 可访问性（语义化标签、键盘操作、aria 属性）；
3. 状态管理的合理性。
```

## 四、结合上下文审查

单独的代码片段往往缺少上下文。有条件时，把相关信息一起提供给 AI，审查会更准确：

```text
背景：这是一个用户登录模块，使用了 React Hook Form 和 axios。
相关文件：请在审查时留意与 authService.js 中 login 接口的配合。
```

## 五、让 AI 给出可执行的修改

审查只是第一步，更好的做法是让 AI 直接给出修复版本：

```text
请针对上面发现的高优先级问题，给出修改后的完整代码，并说明每处改动的原因。
```

## 六、建立审查清单（Checklist）

可以把常见的审查项沉淀成清单，每次审查时要求 AI 逐项核对：

```text
请对照以下清单逐项检查，并标注是否通过：
- [ ] 用户输入是否经过校验与转义
- [ ] 错误处理是否覆盖了异常路径
- [ ] 是否存在硬编码的密钥或敏感信息
- [ ] 循环和查询是否存在性能隐患
- [ ] 命名是否清晰、是否符合项目规范
```

## 七、注意事项

1. **不要盲信**：AI 会误报，每个意见都要人工确认。
2. **敏感代码慎用云端**：涉及核心业务或密钥的代码，优先用本地模型或私有化部署。
3. **配合自动化工具**：AI 审查可以结合 ESLint、SonarQube 等静态检查，效果更好。
4. **沉淀团队规范**：把团队共识的规则写进提示词，让 AI 审查更贴合项目。

## 八、总结

AI 代码审查的价值在于「先扫一遍 + 提醒遗漏」，而不是替代人工。掌握通用模板 + 按语言定制 + 结合上下文 + 要求可执行修改，就能形成一套高效的审查流程，让 Code Review 从「走过场」变成真正有价值的质量门禁。
